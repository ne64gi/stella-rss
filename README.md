# Stella RSS

Kotlin製の独立Android RSSリーダー＋標準ホームウィジェット。StellaShellのコードや権限、Shizukuに依存しません。

[StellaShell](https://github.com/ne64gi/stellashell)とは別のGitリポジトリです。公開先は[ne64gi/stella-rss](https://github.com/ne64gi/stella-rss)。標準AppWidgetとして連携し、サブモジュールや親プロジェクトへの参照は不要です。[切り出し元と履歴](docs/REPOSITORY.md)。

## 使い方

1. 左上の **☰** または左端スワイプでフィードツリーを開き、**＋** からフィード／フォルダ追加・OPML読込／書出。
2. フィード・フォルダを選ぶと、その範囲の記事を時系列表示。上部の「すべて／未読」は選択中の範囲に適用。「あとで読む」に移した記事は通常一覧・未読件数から外れ、保存解除すると戻ります。
3. 記事をタップするとアプリ内の記事画面へ。左右スワイプで前後の記事、下部の **元記事を開く** でブラウザーへ。一覧の行は **左スワイプで既読／右スワイプであとで読むに保存**。長押しメニューで未読に戻す・保存解除もできます。
4. **一覧の一番上で下に引くと更新**（空の一覧でも可）。**↻** からも更新できます。右上 **✓** または **⋮ → すべて既読にする** で選択範囲を一括既読にできます。**⋮** にウィジェット・更新間隔・OPMLを集約。フィードの管理は左側のツリーで行います。
5. ホームのウィジェット一覧からニュース一覧／コンパクトを配置。配信元を **全フィード／選択フィード／フォルダ** から選択し、色・透明度・角丸・文字サイズ等を個別設定。

### フォルダと分類

- フォルダの **⋮ → このフォルダにフィードを追加** から直接登録。フォルダ選択中の上部 **＋** も選択フォルダが登録先になります。追加画面で登録先を確認・変更できます。登録済みURLなら記事・設定を複製せず、そのフォルダへの分類だけ追加します。
- ツリー上部の検索はフィード名・フォルダ名に対応し、親フォルダの経路も残します。検索を消すと元の折りたたみ状態へ戻ります。
- フィードの **⋮ → 編集・表示設定** でその1件だけの詳細画面へ。URL・最終取得状態・表示設定はここに集約。削除は項目メニューから確認して実行します。更新中は「更新完了後に削除します」と案内し、取得処理の終了を待ちます。

- 最大32階層。フォルダ名の左の ▾ / ▸ で開閉、名前をタップすると配下全フィードを統合。
- 同じフィードを複数フォルダに分類可能。**⋮ → 分類を選択（複数可）**。記事は1回だけ保存し、親フォルダの件数・記事・ウィジェットでは重複排除。
- **長押しドラッグ → 移動先フォルダ** で移動。フィードはドラッグ元の所属だけを移動し、他の所属は維持。「未分類」へ落とすとすべての所属を解除。フォルダを「未分類」へ落とすと最上位へ移動。⋮メニューにも移動操作があります。並び順は名前順です。
- フォルダ削除は配下の分類だけを削除。購読と記事は残り、他の所属がなければ未分類に現れます。削除したフォルダを指定していたウィジェットは空表示（全記事へ勝手に切替しません）。
- OPML 2.0はAndroidのファイル選択で入出力。階層と複数所属を保持し、同じURLを重複購読しない追加・統合方式。既存の表示設定・既読・validatorは上書きしません。OPMLは購読一覧形式なので、記事本文・既読・ブックマーク・ウィジェット外観のバックアップは含みません。
- 自動購読なし。フィード別の購読停止、ウィジェット表示、画像、概要の設定は従来どおり使えます。

### コンテナ（任意の拡張機能）

初期状態はOFFです。通常はこれまでどおりフォルダとフィードだけで使えます。

- **⋮ → 拡張機能 → コンテナでニュース空間を分ける** をONにすると、フィードツリー上部に切り替えが現れます。たとえば「日本語圏 ＞ 趣味」「英語圏 ＞ 世界情勢」のような独立した閲覧範囲を作れます。
- コンテナの **⋮** から追加・名前・記事を開いたときの日本語翻訳を設定。一覧・未読件数・あとで読む・一括既読の対象も選択中の範囲になります。
- フィード／フォルダの **⋮ → 別のコンテナへ移動** で移せます。本文・既読・あとで読むは保持します。同じフィードは1コンテナに所属し、その中で複数フォルダへ分類可能。移動時は移動元に残るフォルダへの分類を外します。
- OFFに戻すと全体の一覧へ戻り、コンテナの構成・選択・設定は保存されます。ONに戻せば復元。コンテナの削除は空の場合だけ可能です。
- ウィジェットごとに「すべてのコンテナ」または1つのコンテナを指定できます。フィード／フォルダ指定との共通範囲を表示。拡張OFFでも設定済みウィジェットの範囲は維持します。
- OPMLの読込・書出はONなら選択中のコンテナ、OFFなら通常の全体操作です。OFFでの新規読込・新規購読はデフォルトへ。OPML自体にコンテナ設定は保存しません。別コンテナで登録済みのURLが含まれる読込は、重複作成せず全体を取り消します。

### 端末内翻訳

コンテナを使わなくても、記事画面の **Googleで翻訳** からRSSの見出し・本文（または概要）を日本語にできます。**原文に戻す** ですぐ戻せます。翻訳には [Google Translate / ML Kit](https://developers.google.com/ml-kit/language/translation) を利用します。

- APIキーの登録は不要。最初の言語データ取得だけ通信が必要です（1言語あたり約30MB、Wi-Fiを初期の選択肢として提示）。取得後の文章の翻訳処理は端末内です。RSS取得・記事画像などの通信は別です。
- 元の記事は変更しません。訳文は最大32件・合計8MiBの削除可能なキャッシュへ保存し、同じ本文を再度開いたときに再利用。訳文は保存から7日で期限切れとなり、閲覧では延長しません。期限切れ分は起動・RSS更新・キャッシュアクセス時に削除します。OSが消した場合も再翻訳します。
- フィードの編集画面で自動翻訳を個別に指定できます。コンテナ利用時は親からの継承も可能。自動翻訳は開いた記事と一覧に表示中の見出しが対象で、未取得モデルを勝手にダウンロードしません。必要な場合は **Googleで翻訳** または **翻訳オプション → 言語データを取得** から準備してください。言語データが足りない場合も、翻訳オプションから原文表示に戻せます。
- 一覧の見出しは表示中だけを1件ずつ翻訳し、スクロール・画面停止で古い処理を中止。先読みは行わず、最大512件・2MiBの7日キャッシュを再利用します。**見出しを原文に** で切り替えできます。
- ウィジェット／一覧の全記事の一括翻訳、要約、重要度判定は行いません。長い記事は概要を優先してから翻訳してください。

詳しい範囲・保存・制限は [翻訳とコンテナの設計](docs/READING_SPACES.md)、素材等の表示条件は [第三者表記](THIRD_PARTY_NOTICES.md) を参照してください。

### リーダーの表示

近黒ネイビー／淡いシアン。通常は約106dpの行、見出し最大2行・概要1行、右72dpの画像と細い区切り線。画像なしでは文字に横幅を使います。大きなOS文字設定では行を伸ばして文字の欠けを避けます。選択・未読条件をDBで適用した後に最新1000件を表示し、未読件数自体は全保存記事から集計します。

一覧の横スワイプは既読・保存の一方向操作です。同じ操作を繰り返しても解除されません。変更後は画面下に **元に戻す** を8秒間表示し、直前のスワイプ／一括既読だけ取り消せます（アクセシビリティの操作時間設定に追従）。画面回転を挟んでも維持し、既読を取り消すと未読一覧へ復帰します。未読一覧では既読にした行が消え、すべての記事では残ります。保存した記事は通常の全体／フィード／フォルダ一覧から消え、「あとで読む」にだけ表示されます（ウィジェットの配信条件は従来どおり）。左端からのスワイプは従来どおりフィードツリーです。更新待ち・オフライン待ちは上部に表示し、更新中だけインジケーターが回ります。

**すべて既読にする** は選択中の全体・フィード・配下フォルダを対象にし、表示上限1000件より古い未読にも適用します。通常一覧では「あとで読む」を除外し、「あとで読む」内で実行すると保存記事だけを既読にします。Undoは今回変更した記事だけを未読に戻し、元から既読だった記事・保存状態・後から届いた記事は変更しません。DB構造変更やデータの削除はありません。

### アプリ内の記事画面（0.3.1）

- RSS `content:encoded` / Atom `content` を優先。概要だけの配信はその旨を表示します。サイトの全文抽出や有料壁回避は行いません。
- 右上 **Aa** からダーク／ライト、文字14〜28sp、行間1.3〜2.2倍、余白8〜36dp、画像ON/OFF、本文／概要優先を設定。リーダー専用でウィジェット外観とは独立です。
- 左へスワイプで次、右で前。下部にも前後ボタンがあります。開いた一覧のフィード／フォルダ／未読／あとで読むの範囲・順序を固定するため、既読化で記事を飛ばしません。表示すると既読になり、☆であとで読むへ保存できます。
- 見出し・段落・リンク・画像を安全化して表示。本文リンクは操作後の確認でブラウザーへ渡し、自動遷移やJavaScript実行はありません。
- 保存済み本文・概要はオフラインでも読めます。画像はキャッシュがあれば表示（OSによる削除あり）。旧版で保存した記事は次のフィード更新で本文を補完し、すでに配信から消えた記事は保存済み概要を表示します。
- 各本文／概要は最大256Ki文字、画像はページあたり40件まで。長い内容の保存上限は表示で明示。RSS本文がある場合も元サイトの全文とは限りません。

### ウィジェット

「ダーク」（不透明度98%）と「ガラス」（48%＋薄い縁）、紙、森のプリセットを用意。背景だけ透過し、見出しは不透明のままです。ガラス調は実際の壁紙ぼかしではありません。角丸は0/8/16/24dp、配色・不透明度は各ウィジェット独立です。既存の独自設定は保持し、旧初期配色の完全一致だけ新初期配色へ移行します。

- **ニュース一覧**：小さな左サムネイル＋右見出し（最大3行）、その下に残り4件を各1行、最下部に小さなMore。
- **コンパクト**：左画像＋右タイトルの低い横長カード（標準120dp、最小96dp）。最大5記事＋More、小さいページインジケーター。左右・設定・更新ボタンなし。設定はリーダーの「ウィジェット」から変更できます。
- **横スワイプは標準AppWidget非対応**。コンパクト版は**ページインジケーターのタップ**を代替採用しています。記事が5件未満なら実在記事＋Moreだけを表示します。
- 更新は「更新」ボタン、リーダーでの手動更新、WorkManagerの定期更新（初期60分、15/30/60/180/360分）です。Doze・省電力・通信状態により遅延します。常駐サービスや秒単位ポーリングは使いません。

## 開発・ビルド

Android 8.0/API 26以上。JDK 17、Android SDK 35、Gradle 8.11.1。このリポジトリがGradleルートです。StellaShellのcheckoutや設定ファイルは必要ありません。

```sh
cd stella-rss
./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug :app:assembleDebugAndroidTest
```

APK: `app/build/outputs/apk/debug/app-debug.apk`。パッケージ: `net.fuyumori.stellarss`。開発用署名です。

[Android checks](.github/workflows/android-checks.yml) は、このリポジトリのpush／Pull Requestでunit・lint・APKビルドを実行します。実機テストやAPK公開は行いません。

実機確認では、自分の端末のIPアドレスとADBポートを指定してください。以下の `DEVICE_IP:ADB_PORT` は実行前に置き換えてください。

```sh
adb connect 'DEVICE_IP:ADB_PORT'
adb -s 'DEVICE_IP:ADB_PORT' install -r app/build/outputs/apk/debug/app-debug.apk
adb -s 'DEVICE_IP:ADB_PORT' install -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb -s 'DEVICE_IP:ADB_PORT' shell am instrument -w net.fuyumori.stellarss.test/androidx.test.runner.AndroidJUnitRunner
```

画面操作試験にはロック解除済みの実機が必要です。端末設定の書換え、既存アプリのデータ削除、ホーム選択変更は行いません。実機テストのAppWidgetHostは独立のdebug専用Activityを使い、自分が割り当てたwidget IDと合成fixtureだけを後片付けします。
