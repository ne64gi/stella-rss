# 閲覧コンテナと端末内翻訳

## 所有者と保存

- `ReadingSpaces` が拡張ON/OFF・選択・コンテナCRUD・コンテナ間移動・翻訳方針の解決を担当する。UIの `SpaceControls` はその窓口だけを使う。
- Room v4→v5は既存フィード／フォルダの `containerId=1`、`containers` のデフォルト行、フィードのnullable翻訳方針、ウィジェットのnullable表示範囲を追加する。既存記事・本文・既読・保存・ウィジェット外観を変更しない。初期は拡張OFF。
- `Library.inContainer(null)` は全体、ID指定はその所属だけを返す。コンテナ条件は一覧／Widget／一括既読のSQLにも渡し、LIMITより前に適用。UIに古いFeed IDが残っていても移動済みの別コンテナ記事を表示・変更しない。範囲が空／削除済みでも全体へフォールバックしない。
- 記事の所有者は引き続きFeed。コンテナ移動でArticleのIDや本文を再生成しない。FeedのURLは全体で一意なので同じ購読を別コンテナへ複製しない。
- コンテナIDの整合性は `ReadingSpaces` / `Organization` / `Repository.saveFeed` のトランザクションで検証する。追加列にDB外部キーはないため、UIや新しい機能からDAOへ直接組織変更を書き込まない。
- フォルダ移動は配下のフォルダと分類されたFeedを一括移動し、移動範囲外の分類だけ解除。移動先の同名ルートフォルダ、異なるコンテナ間の通常分類、内容のあるコンテナ削除を拒否する。
- OFFは削除操作ではない。選択・組織・翻訳方針・既存Widgetの範囲を保持する。コンテナから継承する自動翻訳だけ停止する。Feed明示指定の自動翻訳は単独機能として引き続き有効。
- 同名フォルダは別コンテナで使用可能。OFFの全体表示では同名項目も並ぶ。OFFにしてもコンテナ間の分類を暗黙に混在させない。
- OPMLは選択コンテナのフォルダ／購読交換形式。コンテナ設定や記事のバックアップではない。OFF時は全体を書出し、デフォルトへ読込。別コンテナ既存URLとの衝突はトランザクション全体をロールバックする。

## 翻訳

`ReaderTranslation`（表示・ライフサイクル） → `TranslationEngine`（原文・キャッシュ・プロバイダー所有） → `TranslationProvider`（識別・モデル準備・翻訳）に分離。現在の実装は `MlKitTranslation` のみ。翻訳処理に外部HTTP APIクライアントやキー保存機能はない。

1. 現在表示するRSS本文／概要を `ArticleHtml.source` で安全化する。
2. エンジン版・日本語という翻訳先・見出し・選択本文のSHA-256でキャッシュを確認する。
3. キャッシュがなければ同梱言語識別器で判定。必要な翻訳モデルがなければ、手動操作時だけWi-Fi／モバイル通信許可の選択を提示する。英語は組込みモデルのためリモートモデル扱いしない。
4. HTML文字列を翻訳APIへ渡さず、本文のテキストノードを順に処理する。リンク先・画像・コードは維持。訳文はテキストとして挿入し、表示時も通常のHTML許可リストを通す。インライン要素単位の翻訳なので文脈や文体の品質には限界がある。
5. 元のRoom記事は変更しない。訳文キャッシュは `cacheDir/translations`、最大32件・8MiB・1エントリ1MiB。保存から7日で期限切れとなり、閲覧で延長しない。旧形式の期限なしキャッシュは再生成する。期限切れの訳は利用せず、起動・通常のRSS更新・キャッシュアクセス時に削除する（削除専用のタイマーや定期ジョブは増やさない）。破損・削除時は再生成する。キャッシュヒット時はSDKの翻訳器を作らない。

対象は最大32,000文字／512テキストノード、1回のモデル入力は最大2,000文字。長すぎる場合は途中までを完全な訳と扱わず、概要へ切り替える案内を出す。翻訳結果もサイズを検証する。コード・画像内文字・リンク先Webページの全文は翻訳しない。翻訳先は初期実装では日本語のみ。

記事切替・画面停止・中止でコルーチンを取り消し、古い結果の反映を防ぐ。翻訳器と言語識別器は要求ごとに `finally` で閉じる。画面外の全文翻訳、サービス、タイマー、定期的モデル更新チェックは追加しない。SDK側で開始したモデルダウンロードは、画面の翻訳待ちを中止しても継続する場合がある。

記事の表示設定を変更した場合は原文へ戻す。アクティビティ再作成では翻訳表示の選択を保存せず、手動で再度翻訳するとキャッシュを利用する（自動翻訳ONなら再適用）。OSキャッシュ削除は原文や既読状態に影響しない。

モデルの取得はネット接続が必要。その後の文章の翻訳は端末内。アプリ全体のネット通信を禁止する機能ではなく、RSS・画像・モデル取得やSDK診断通信とは区別する。言語モデルはSDKの管理領域で保持され、訳文キャッシュの8MiB制限には含まれない。言語モデルを多数取得するとその分ストレージを使う。

日本語以外同士の翻訳は英語を経由する。品質は原文と照合し、高度な専門翻訳や要約の代替としない。翻訳UIはGoogle表記と提供されたバッジを表示する。

## 一覧の見出し翻訳

コンテナ／フィードの自動翻訳方針を継承し、**実際に画面へ表示されている見出しだけ**を日本語にする。266件など未読全体を処理しない。スクロール・レイアウト変更を200msまとめ、1件ずつ順番に翻訳する。先読みは行わない。1回の表示要求は最大20件に制限し、スクロール先が変わったら古い要求をキャンセル、画面停止でも待機・翻訳を中止する。言語識別器・翻訳器は1要求につき1組のみ保持し、処理終了・中止時に閉じる。

見出しキャッシュは `cacheDir/headline-translations`、最大512件・2MiB。本文同様、保存から7日で失効し再閲覧で延長しない。同じ見出しなら再利用し、原文が変わると別キーになる。原文・既読・保存状態は変更しない。「見出しを原文に」で一覧を原文へ戻せる。画面を開き直したときの翻訳はキャッシュから再利用する。

モデルが不足している場合は原文を維持し「見出しの翻訳を準備」を表示する。自動ダウンロードせず、利用者がWi-Fiまたはモバイル通信許可を選ぶ。訳文保存の7日期限は言語モデルには適用せず、モデルを毎週再取得する処理はない。Widgetはこの版では原文表示を維持し、バックグラウンドでの見出し翻訳は行わない。

## 今回の範囲外と検証境界

コンテナ別の更新間隔・要約・重要度選別、Widgetの見出し自動翻訳、フィード間の方針継承の多段上書き、モデル管理画面は未実装。コンテナ→Feedの方針継承だけを扱う。

Room移行・所属・既読保持・表示範囲・キャッシュ・キャンセル時解放は自動テストで検証する。ML Kitの実際のモデル取得／オフライン品質／端末メモリと電池／PhoneとDesktopの画面操作は別の実機検証が必要。SDKがコンパイルできたことと実機で翻訳できたことを混同しない。
